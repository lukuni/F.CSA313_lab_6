## Хэсэг A: Category-Partition гараар — Шилжүүлгийн функц

Тестлэх функц: `POST /transfer { "from": ID, "to": ID, "amount": NUM, "currency": CODE }`  
Амжилт: `201 {"result":"OK"}` · Оролтын алдаа: `200 {"result":"ERROR_..."}`

### Даалгавар A1 — Сонголт ба төлөөлөх утгууд

| # | Параметр / орчин | Сонголт (категори) | Төлөөлөх утгууд |
|---|---|---|---|
| 1 | `from` | Илгээгч дансны төлөв | хүчинтэй (байгаа, царцаагдаагүй) · царцаагдсан · байхгүй |
| 2 | `to` | Хүлээн авагч дансны төлөв | хүчинтэй (байгаа, `from`-оос өөр) · байхгүй · `from`-тэй ижил |
| 3 | `amount` | Дүнгийн тэмдэг | эерэг (жишээ нь 100 000) · тэг (0) · сөрөг (−100) |
| 4 | `amount` + орчин | Хөрвүүлсний дараах дүн ба дансны үлдэгдэл | үлдэгдлээс бага · үлдэгдэлтэй яг тэнцүү · үлдэгдлээс их |
| 5 | `amount` + орчин | Хөрвүүлсний дараах дүн ба өдрийн үлдсэн лимит (лимит − өнөөдөр ашигласан) | үлдсэн лимитээс бага · яг тэнцүү · их |
| 6 | `currency` | Валют | дансны валюттай ижил · өөр (ханшаар хөрвүүлнэ) |

**Далд орчны сонголтууд.** Хүсэлтийн body-д байхгүй боловч үр дүнг тодорхойлдог гурван орчны хүчин зүйл бий: `from` дансны үлдэгдэл, өнөөдөр аль хэдийн шилжүүлсэн дүн (өдрийн лимит хэр дүүрсэн), валютын ханш. Иймээс 4 ба 5-р категорийг `amount`-ийн тогтмол утгаар биш, *хөрвүүлсний дараах дүн ба орчны харьцаагаар* тодорхойлсон. Жишээ нь 50 USD гэсэн нэг ижил хүсэлт үлдэгдэл, ашигласан лимит, ханшаас хамаарч OK, ERROR_INSUFFICIENT эсвэл ERROR_LIMIT гэсэн өөр өөр хариу өгнө.

**Тодорхойлолтод тусгаагүй зүйлс** (A3-т оруулаагүй, нээлттэй асуулт): танигдахгүй валютын код (жишээ нь `"XYZ"`), `to` данс царцаагдсан бол юу болох, `amount` тоо биш эсвэл бутархай оронтой байх, талбар дутуу байх.
